# Qt 5.12.10 UI逐项绑定与字符注册表编译基准

> **架构验证通过：新方案的 UI 只保存字符功能标识，经一个统一动作路由器查找并执行普通 C++ 功能类；UI 与路由代码均不引用具体功能类型。**

*测试时间：2026-08-17 · Qt 5.12.10 · MSVC x64 · Debug · 200 个功能 · 5 次采样*

## 结论摘要

- **两组都实际从 `QAction::trigger()` 进入业务逻辑。** 旧组逐项连接 200 个功能槽；新组只连接一次 `QActionGroup::triggered`，从 `QAction::data()` 读取 `feature.NNN` 后查找注册表。
- **干净编译由 17.75 s 变为 6.97 s，耗时减少 60.7%。**
- **单功能实现变化由 689 ms 变为 330 ms，耗时减少 52.2%。**
- **单功能头变化由 1.46 s 变为 347 ms，耗时减少 76.2%。**
- **MOC 数量由 200 降为 0。** 新功能类不依赖 `QObject`、槽函数或 UI，可由菜单、工具栏、脚本和测试共同复用。
- **这是完整架构重构的综合结果。** 差异同时包含字符路由、UI依赖隔离、独立工厂和普通 C++ 功能类的影响，不能全部归因于字符串查找。

| 干净编译耗时 | 单实现增量耗时 | UI头变化耗时 | 新方案MOC |
|---:|---:|---:|---:|
| **-60.7%** | **-52.2%** | **-12.8%** | **0** |

## 真实调用链

```text
QAction::trigger()
  → QActionGroup::triggered(QAction*)
  → ActionRouter读取QAction::data()
  → FunctionRegistry按feature.NNN查找
  → IFunction::execute(FunctionInvocation)
  → BusinessContext::run()
```

CTest还验证了全部200次成功调用、固定校验和、未知字符查找失败以及重复标识注册失败。新UI入口和`ActionRouter`中不存在`FunctionN`具体类型引用。

- **干净编译：** 清理目标产物后完整编译。
- **空构建：** 源码无变化时再次执行构建。
- **单实现增量：** 仅触碰一个功能实现文件。
- **单功能头变化：** 触碰一个具体功能类头文件，观察依赖传播。
- **UI头变化：** 触碰共享UI上下文头文件。
- **业务头变化：** 触碰全部功能共同依赖的业务头文件。

## 可信度与适用边界

- 两组均通过CTest并产生相同固定校验和，实际动作触发链已验证。
- MOC数量已验证为 `200 / 0`，符合旧组200个功能槽、新组普通C++功能类的设计。
- 5次交错采样降低了固定顺序和机器升温偏差，但不等价于硬件实验室测试。
- 这是完整重构前后对照，而不是只替换查找键的单变量实验；结果不能全部归因于字符串映射。
- 合成工程用于让依赖差异超过计时噪声，百分比不能直接外推到真实项目。
- 未启用预编译头、Unity Build、ccache或sccache。

## 建议的真实工程验证

1. 选择10–20个现有逐项槽绑定功能，改用字符串注册表并保持业务算法不变。
2. 分别修改UI头、单个功能头和公共业务头，记录实际重编译对象数。
3. 对确有信号、属性或QML需求的功能保留QObject，其余功能使用普通C++接口。
4. 保持真实工程现有PCH、Unity Build和并行配置不变，再进行A/B计时。
