# 公开仓库发布检查清单

本清单用于提交、Pull Request、打标签或发布公开材料前的最终核验。检查范围同时包括当前工作区、暂存区和完整 Git 历史；`.gitignore` 只能阻止新的误提交，不能清除已经进入历史的内容。

## 自动预检

在仓库根目录运行：

```powershell
.\scripts\Test-PublicRelease.ps1
```

脚本扫描 Git 已跟踪文件、未忽略的未跟踪文本文件和全部提交补丁，检查常见 Windows 用户目录、私网地址、内部域名、令牌形状、秘密赋值和私钥头。失败信息只显示类别与文件或提交，不回显疑似秘密。

自动检查是轻量防线，不能替代人工审核。`C:\Qt`、`C:\Program Files` 等公开工具路径不属于用户目录，不应仅因存在绝对路径就判定为泄露。

## 工作区与暂存区

- [ ] `git status --short` 中只有本次变更需要的文件。
- [ ] 已逐行检查 `git diff` 和 `git diff --cached`。
- [ ] 没有提交 `benchmark-builds/`、`benchmark-results/`、`build*/`、`.vs/`、`out/` 或原始日志。
- [ ] 没有提交 `.env`、编辑器配置、崩溃转储、缓存或临时文件。
- [ ] 文档、报告、CSV、JSON 和日志中没有用户名、机器名或用户配置目录。
- [ ] 没有私网地址、内部域名、企业仓库地址、客户名、项目代号或工单链接。
- [ ] 没有密码、令牌、密钥、Cookie、连接字符串或私钥材料。
- [ ] 截图、二进制文件和压缩包已人工检查；自动脚本不会解析这些格式。
- [ ] `.gitignore` 覆盖所有本地生成目录，但没有用忽略规则掩盖本应删除的已跟踪文件。

建议同时运行：

```powershell
git status --short --ignored
git diff --check
git diff --cached
git ls-files benchmark-builds benchmark-results build out .vs
```

## Git 历史

- [ ] 已确认当前分支从预期的公开基线创建，没有混入内部提交。
- [ ] 已查看提交列表和文件统计，确认没有异常的大文件或历史文件名。
- [ ] 对已知的用户名、机器名、内部域名和客户代号执行了历史搜索。
- [ ] 已确认被删除的秘密没有残留在旧提交、标签或其他分支中。

可使用以下命令做定向检查，其中 `$suspect` 只在本机终端设置，不应写入仓库：

```powershell
git log --all --oneline --stat
$suspect = Read-Host '输入需要检查的本机敏感词'
git log --all -S $suspect --oneline
git rev-list --objects --all
```

## 验证与发布批准

- [ ] `.\Run-Benchmark.ps1 -Quick` 通过。
- [ ] 文档中的公开数据已脱敏，并且仍能解释测试环境与结论边界。
- [ ] PR 描述包含变更、原因、验证、风险和关联 Issue。
- [ ] 至少一名维护者复核了自动检查无法判断的组织名称、客户信息和截图。
- [ ] 发布人确认最终提交 SHA 与已审查 SHA 一致。

## 发现敏感信息时

1. 立即停止推送、合并、打标签和发布，不要在 Issue 或 PR 中粘贴秘密原文。
2. 对令牌、密码、密钥和连接字符串先执行撤销或轮换；删除文件不能使已泄露凭据恢复安全。
3. 通知维护者并确认影响范围，包括 Fork、缓存、构建产物和已经下载的克隆。
4. 如果内容尚未进入远程历史，从工作区或本地提交中移除后重新运行全部检查。
5. 如果内容已经进入 Git 历史，先备份并制定历史重写方案，可使用 `git filter-repo` 删除相关路径或文本。强制推送前必须获得维护者批准，并通知所有协作者重新克隆或清理旧引用。
6. 清理后再次扫描所有分支和标签，确认远程缓存、Release 附件和 CI Artifact 也已处理，再恢复发布。

历史重写会改变提交 SHA，属于团队级破坏性操作，不能由单个贡献者自行执行。
